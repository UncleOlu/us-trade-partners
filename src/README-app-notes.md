# App notes (Agent B)

## Base path

`VITE_BASE_PATH` (default `/us-trade-partners/`) is the single source of truth for:

- Vite `base` (vite.config.ts)
- React Router `basename` (`src/lib/config.ts` -> `ROUTER_BASENAME`)
- Every data fetch URL (`src/lib/config.ts` -> `dataUrl()`)

Set it before `npm run dev` / `npm run build` if the app is served from a different path, e.g.:

```
VITE_BASE_PATH=/some-other-path/ npm run build
```

## Snapshot id

`reports/pipeline/last_snapshot_id.txt` (owned by Agent A) is read once, at Vite config
load time, and injected as the build-time constant `__SNAPSHOT_ID__`
(`src/vite-env.d.ts`, `src/lib/config.ts`). Source code never hard-codes a
snapshot id.

## Data serving

`data/<snapshot_id>/` is served under `${VITE_BASE_PATH}data/<snapshot_id>/` in
both dev (a Vite middleware in vite.config.ts) and build (a `closeBundle` copy
step into `dist/data/<snapshot_id>/`). Only the current snapshot is copied.

`docs/methodology-content.md` is served the same way, at
`${VITE_BASE_PATH}methodology-content.md`, so the methodology page has one
source of truth instead of a duplicated copy under src/.

## Generated types

`src/types/generated.ts` is generated by `npm run gen:types`
(`scripts/gen-types.mjs`) from `schema/*.schema.json`. Do not hand-edit it.

## Local development needs data/<snapshot_id>/ on disk

The published snapshot no longer lives in git history. `data/<snapshot_id>/`
is expected to already be gitignored and present on disk before you run `npm
run dev` or `npm run build` locally; `vite.config.ts` reads
`reports/pipeline/last_snapshot_id.txt` for the id and fails immediately if
`data/<that id>/` is missing. Get it one of two ways:

- Run the pipeline locally (`make data`, see the repository root `Makefile`),
  which writes `data/<snapshot_id>/` directly, or
- Download and unpack the matching GitHub Release: find the tag
  `snapshot-<snapshot_id>` in the repository's Releases, download
  `<snapshot_id>.zip`, verify it against the published `<snapshot_id>.zip.sha256`
  (`shasum -a 256 -c`), and unzip it into `data/<snapshot_id>/` so that
  `data/<snapshot_id>/meta.json` exists.

`.github/workflows/deploy.yml` does the second path automatically on every
deploy, using `gh release download` plus a sha256 check, and fails the build
if the asset is missing or the checksum does not match. It never falls back
to a different snapshot.
